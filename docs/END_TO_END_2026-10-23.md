## Continuous flow actually executed

1. Two isolated 390×844 browser contexts complete authorization code + PKCE through the loopback test issuer. Each creates an account/profile in public community mode, without invitations or ticket records.
2. Each explicitly enables profile discoverability and event-directory visibility. Alice refreshes the off-site directory and opens Bob's actual API-backed profile. Both accounts still have zero venue-presence records and zero discovery shares. Meetup action is disabled before arrival.
3. Each explicitly checks in through foreground browser GPS at a disposable approved synthetic venue, then separately enables Nearby. The persisted server expiry is checked against exactly 30 minutes, with no auto-enrollment/location side effect from signup.
4. Alice sees Bob's declared interests and meeting intent in the venue directory/Nearby list. She proposes a reason/time and a synthetic public landmark. Bob explicitly acknowledges the saved notification and accepts. Directions and a real downloaded calendar file are checked; the calendar excludes the private meeting reason.
5. Bob cancels/proposes another time; Alice accepts the rescheduled meeting.
6. Each opens the other's canonical profile QR link and explicitly follows. Alice saves a private note; the database/API proves Bob's corresponding note is empty. Mutual chat delivers Alice's message to Bob's separate browser.
7. Alice stops discovery; the UI shows hidden location. Her venue presence is then removed through the sandbox API and the UI is refreshed. API `onSite=false` and zero Alice share records are asserted.
8. Alice opens the retained connection and sends a second message after departure. Bob receives it in his existing browser. No GPS/presence is needed to keep the relationship.

All assertions completed, with no browser page errors. Final command exit 0. The initial extension attempt had an overly exact accessibility selector for the event-directory checkbox (its accessible name includes help text); that test selector was corrected. Both the corrected base journey and the final departure-enhanced journey pass. The unsuccessful selector attempt is retained, not counted as a passing run or an application defect.

## Boundaries

This test uses a real disposable MongoDB, real running application routes, actual React rendering, independently signed sandbox OIDC identities, actual HTTP/socket requests and persisted database assertions. The GPS points, identities and venue are synthetic fixtures, never written to Atlas. QR testing uses the canonical profile-link fallback; no physical camera scan is claimed. BLE backend authorization is not a radio test. A browser download is not a phone installation. Real-provider two-person acceptance, real event geofencing/landmarks, device permissions, Bluetooth interoperability, battery/foreground behavior and physical camera scanning remain unverified.

The APK verifier now also records `minSdkVersion` and `targetSdkVersion` from the actual signed manifest when verifying a finished artifact. SDK metadata does not prove operational compatibility on every Android device. No real attendee location test, real meetup/message, public APK publication, paid upgrade or application-source redeployment was performed for this verification. After verification, only the private signed APK pair was updated on the existing VM; the service reloaded its metadata.
